# Defensive Cybersecurity — ความปลอดภัยเชิงป้องกัน

## 1. หลักการพื้นฐาน
- Confidentiality: ข้อมูลเข้าถึงได้เฉพาะผู้มีสิทธิ์
- Integrity: ข้อมูลถูกต้องและไม่ถูกแก้ไขโดยไม่ได้รับอนุญาต
- Availability: ระบบพร้อมให้บริการ
- Least privilege: ให้สิทธิ์เท่าที่จำเป็น
- Defense in depth: ใช้มาตรการป้องกันหลายชั้น

## 2. การจัดการบัญชี
- ใช้ MFA เมื่อรองรับ
- ใช้รหัสผ่านไม่ซ้ำและ password manager
- ปิดบัญชีที่ไม่ใช้งาน
- แยกบัญชีผู้ดูแลระบบจากบัญชีใช้งานทั่วไป
- ตรวจสอบสิทธิ์และทบทวนเป็นระยะ

## 3. Patch และ Configuration
- ทำ inventory ของ OS, software และ firmware
- ประเมินความสำคัญและผลกระทบก่อน patch
- ทดสอบในระบบ staging หากทำได้
- สำรองข้อมูลและเตรียม rollback
- ปิด service/port ที่ไม่จำเป็น
- เปลี่ยนค่า default credentials

## 4. Log ที่ควรติดตาม
- Authentication success/failure
- การสร้าง/ลบบัญชีและเปลี่ยนสิทธิ์
- การเปลี่ยนแปลง firewall/network configuration
- Service start/stop และ application errors
- Endpoint protection alerts
- การใช้งานทรัพยากรผิดปกติ

## 5. เมื่อสงสัยเครื่องติดมัลแวร์
1. บันทึกอาการ เวลา และผู้แจ้ง
2. ทำตาม incident response policy ขององค์กร
3. แยกเครื่องออกจากเครือข่ายเมื่อมีความเสี่ยงแพร่กระจาย โดยประสานผู้รับผิดชอบ
4. อย่าลบ log หรือรีบติดตั้งใหม่ก่อนเก็บหลักฐานที่จำเป็น
5. ตรวจ endpoint alerts, processes, startup items และ network connections ด้วยเครื่องมือที่ได้รับอนุญาต
6. เปลี่ยน credentials จากอุปกรณ์ที่เชื่อถือได้เมื่อสงสัยว่ารั่วไหล
7. กู้คืนจาก backup ที่ตรวจสอบแล้ว และติดตามหลังกลับมาใช้งาน

## 6. Phishing
สัญญาณที่ควรระวัง:
- เร่งให้กดลิงก์หรือโอนเงิน
- ชื่อโดเมนสะกดคล้ายของจริง
- ไฟล์แนบที่ไม่คาดคิด
- ขอรหัสผ่าน, OTP หรือข้อมูลลับ
แนวทาง: อย่ากดลิงก์ ตรวจสอบผู้ส่งผ่านช่องทางอื่น และรายงานทีม IT/Security

## 7. การประเมินความเสี่ยง
พิจารณา:
- Asset: สิ่งที่ต้องปกป้อง
- Threat: เหตุการณ์หรือผู้คุกคาม
- Vulnerability: จุดอ่อน
- Likelihood: โอกาสเกิด
- Impact: ผลกระทบ
จัดลำดับแก้ไขตามความเสี่ยง ไม่ใช่ดูคะแนนช่องโหว่อย่างเดียว

## 8. ขอบเขตการทดสอบ
ทำ vulnerability scanning หรือ penetration testing เฉพาะระบบที่ได้รับอนุญาต ระบุ scope, เวลา, วิธีทดสอบ และผู้ติดต่อฉุกเฉินก่อนเสมอ
